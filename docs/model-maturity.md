# Модель версии 2

В ветке `feat/model-maturity-dp-mpc` локальный минимум расхода заменен связанной задачей управления скоростью по маршруту.

## Архитектура

- `profile_model.py` — очистка, пространственный ресэмплинг, сглаживающий сплайн, уклон, кривизна и доверие к восстановленным точкам.
- `vehicle_model.py` — дорожные сопротивления, приведенная масса, ограничения тяги/торможения, передача, приближенная карта КПД, fuel cut-off и расчет перехода между скоростями.
- `optimization.py` — projected pointwise baseline, глобальное динамическое программирование и receding-horizon MPC.
- `config.py` и `configs/default.yaml` — воспроизводимая конфигурация маршрута, автомобиля и оптимизатора.

## Состояние и динамика

Состоянием служит скорость на пространственной сетке. Для перехода на сегменте вычисляется

\[
a_k = \frac{v_{k+1}^2-v_k^2}{2\Delta s_k}.
\]

Требуемая тяга включает инерцию, аэродинамику, качение и уклон. Топливо интегрируется по времени сегмента. DP минимизирует топливо, время, тормозную энергию и штраф ускорения при ограничениях скорости, бокового ускорения, продольного ускорения, силы и мощности.

## API

- `/api/route?algorithm=pointwise`
- `/api/route?algorithm=dp`
- `/api/route?algorithm=mpc`
- `/api/metrics`

Ответ сохраняет поле `speed_optimal` для совместимости интерфейса и дополнительно возвращает ускорение, тягу, торможение, передачу, обороты, сегментный расход, накопленные топливо и время, а также доверие к профилю.

## Проверка

```bash
pip install -r webapp/requirements.txt -r requirements-dev.txt
pytest
ruff check webapp tests
uvicorn webapp.app:app --reload
```

CI выполняет тесты на Python 3.10 и 3.12. Перед интерпретацией экономии требуется откалибровать модель по реальным OBD/CAN/GPS данным; текущая карта КПД является физически осмысленной аппроксимацией, а не идентифицированной картой конкретного двигателя.
