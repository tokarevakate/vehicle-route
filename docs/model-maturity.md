# Модель версии 2

В ветке `feat/model-maturity-dp-mpc` локальный минимум расхода заменён связанной задачей управления скоростью по маршруту. Объём проекта ограничен задачами курсовой работы: сохраняются исходный pointwise baseline и основной метод динамического программирования.

## Архитектура

- `profile_model.py` — очистка, пространственный ресэмплинг, сглаживающий сплайн, уклон, кривизна и доверие к восстановленным точкам.
- `vehicle_model.py` — дорожные сопротивления, приведённая масса, ограничения тяги и торможения, выбор передачи, аналитическая аппроксимация КПД, fuel cut-off и расчёт перехода между скоростями.
- `optimization.py` — физически допустимый pointwise baseline и глобальное динамическое программирование.
- `config.py` и `configs/default.yaml` — воспроизводимая конфигурация маршрута, автомобиля и оптимизатора.

## Состояние и динамика

Состоянием служит скорость на пространственной сетке. Для перехода на сегменте вычисляется

\[
a_k = \frac{v_{k+1}^2-v_k^2}{2\Delta s_k}.
\]

Требуемая тяга включает инерцию, аэродинамическое сопротивление, сопротивление качению и уклон. Топливо интегрируется по времени сегмента. DP минимизирует сумму модельного расхода топлива, штрафа времени, тормозной энергии и ускорения при ограничениях скорости, бокового и продольного ускорения, силы и мощности.

Реальная карта двигателя не используется: зависимость эффективности от режима задаётся аналитической аппроксимацией. Поэтому результаты предназначены для сравнительной оценки алгоритмов, а не для точного прогноза расхода конкретного автомобиля.

Маршрут заранее задан координатами из CSV, поэтому построение дорожного графа и выбор маршрута не входят в задачи проекта.

## API

- `/api/route?algorithm=pointwise`
- `/api/route?algorithm=dp`
- `/api/metrics`

Ответ сохраняет поле `speed_optimal` для интерфейса и дополнительно возвращает ускорение, тягу, торможение, сегментный расход, накопленные топливо и время. Передача, обороты двигателя и доверие к профилю остаются диагностическими полями модели.
